# Repository recon — 2026-10-22

Read-only inspection of `living-world` plus a full local build/test run. Every claim below was checked against the
working tree or a command run today; file references are `path:line`. Nothing in the code was changed by this recon.

> Follow-up: the adversarial pass in [`adversarial-2026-10-22.md`](adversarial-2026-10-22.md) re-tested these claims,
> failed 13 of 14 invariant probes outright (the 14th passed only its conservation assertion), and corrected three
> statements in this document.

## 0. Executive summary

The kernel is in better shape than the surrounding product: invariants, Python tests, mirror parity, the committed
goldens, `:game-core:jvmTest` and the full `./gradlew check` all pass locally. The documented 90-day fingerprint
(`041e2593769b807b`) and its economy claims reproduce exactly.

The largest real gaps are not in the simulation maths:

1. **The Android app has four private copies of the world and never ticks or saves it.** Each screen mutates its own
   `WorldState`, so a trade, a relationship change or a death is invisible to the other tabs and is lost when the
   Activity is recreated.
2. **CI never compares Kotlin output with `tests/golden/`.** Only the Python mirror is held to the goldens in CI; the
   Kotlin→golden check lives in the local agent stop gate, which CI never runs and which does not require git hooks.
3. **Two item-conservation bugs:** theft never gives the item to the thief (and theft from the player removes
   nothing), and a trade pays the seller even when the seller has no stock, creating the item from nothing.
4. **The reducer is not idempotent per event id:** it refuses to record a duplicate event but re-applies its effects.
5. **Shipping blockers are untouched:** `targetSdk 34` (Play requires 36 from 2026-08-31), a placeholder app icon, and
   a 345 MB model directory inside the Auto Backup scope with no backup rules.

## 3. Findings

### 3.1 The Android shell has four worlds, no clock and no save

- `MainActivity` builds one `marketVillage()` (`androidApp/src/main/kotlin/com/livingworld/game/android/MainActivity.kt:216`)
  and hands the same reference to four view models (`:219`, `:224`–`:226`), but each stores its own `private var world`
  (`DialogueViewModel.kt:46`, `MapViewModel.kt:25`, `InventoryViewModel.kt:25`, `MainActivity.kt:56`). `WorldState` is
  immutable, so every `world = reducer.apply(...)` updates only that screen.
- Consequences, all observable in code: a dialogue trust change is invisible to the map and inventory; travelling in
  `MapViewModel` leaves `DialogueViewModel`'s player in `village_square`; killing `miner_derek` in the duel does not
  affect any other tab; Activity recreation re-runs `marketVillage()` and discards every event.
- `SaveManager` is only imported by `desktopApp` (`InspectorMain.kt:9`, `:45`, `:52`). The app has no save, no load and
  no tick loop; `SimulationEngine` is never constructed in `androidApp`.
- The four `currentWorldState` getters are public but only tests use them; there is no shared state holder.

### 3.2 Item and event conservation

- **Theft removes but never transfers.** `applyTheft` updates witnesses and subtracts the item from an NPC owner
  (`WorldReducer.kt:219`–`:256`). It never adds the item to the thief, and when the owner is the player it looks up an
  NPC named `player` (none exists), so stealing from the player removes nothing. A stolen object leaves the world.
- **Trade can mint goods.** `applyTrade` credits the seller `paid` and does
  `sellerNpc.resources.items - event.item` (`WorldReducer.kt:398`). `List.minus` is a no-op when the item is absent, so
  a merchant with no bread still gets paid and the buyer still receives bread. There is no `isAlive` check either, so a
  dead merchant will still trade.
- **The reducer is not idempotent per event id.** `apply` avoids recording an event twice (`WorldReducer.kt:29`–`:36`)
  but then runs the event branch unconditionally. `WorldReducerTest.applying_the_same_event_twice_records_it_once`
  asserts only the ledger (`WorldReducerTest.kt:42`–`:47`), while
  `current_behaviour_killing_the_dead_again_repeats_the_cascade` pins the double cascade (`:438`–`:443`). Any retry or
  overlapping replay that re-applies a recorded event corrupts state while keeping one ledger entry.
- **Starvation is not modelled and every death is a murder.** Routine food is clamped to `0.5` (`WorldReducer.kt:554`)
  and nothing deals hunger damage, so an NPC cannot die of hunger. The 90-day run ends with every NPC at food 11–96.
  `ProceduralQuestEngine` turns every `NpcKilled` into a `HOMICIDE` problem (`WorldState.kt:84`–`:96`) and every such
  problem into a guard-captain quest (`:143`–`:160`).
  The 10-day turmoil run produces “Investigate the Murder of farmer_elena” for a death recorded with `killer = null`
  (`lw_mirror/scenarios.py` seeds the same case).
- **The duel is one-sided.** `TacticalDuelViewModel.executeDuelRound` creates one `NpcAttacked` event with the player as
  attacker (`MainActivity.kt:108`) and rebuilds a fresh 100-health proxy NPC each round (`:81`); the opponent never
  attacks and `PlayerState` has no health field (`WorldState.kt:203`–`:215`).
- **Dialogue hardcodes the player id.** `EntityId.Player("player")` is constructed in four places
  (`DialogueViewModel.kt:79`, `:105`, `:116`, `:179`) instead of using `world.player.id`. It works only because
  `PlayerState.id` defaults to the same string.

### 3.3 Determinism is asserted more narrowly than documented

- `SaveManager.computeDeterministicFingerprint` claims to cover the “complete authoritative WorldState”, but hashes only
  alive/health/coins/food/occupation and belief/memory **counts** per NPC, faction enemies, relationship sentiment,
  and item prices (`SaveManager.kt:104`–`:145`). Belief content, memory content, emotional state, traits, items,
  treasury, scarcity, quests and the whole player are absent, and health/coins are truncated to hundredths via
  `toInt()`.
- `ReplayDeterminismTest.deterministic_event_replay_matches_live_simulation` compares only `time` and `npcs`
  (`ReplayDeterminismTest.kt:26`–`:29`); the 90-day soak compares only `npcs` between two runs (`:39`–`:45`). Economy,
  relationships, quests and the ledger are not asserted.
- The committed goldens are 10 days. The default 90-day run records **zero** rumours, deaths, attacks, thefts or quests,
  so the default golden cannot detect a regression in those systems; only the seeded turmoil/feud scenarios exercise
  them, and only at day 0 plus 10 days of consequences.

### 3.4 AI and model delivery

- The production attach path checks only file **size**: `ModelDownloader.isInstalled` calls `ModelIntegrity.sizeProblem`
  (`AiSetup.kt:106`–`:107`), used by `AiController` at `:147` and `:171`. The sha256 is verified during download but never
  again, so a same-size corrupted or replaced file is treated as installed.
- `AndroidModelAssetManager`, which does implement `verifyChecksum` (`AndroidModelAssetManager.kt:27`–`:46`), is used only
  by `ModelAssetIntegrityTest`; it is dead production code. `DeterministicAiFallback` is likewise used only by a test,
  and `extractLastJsonObject` / `isFallbackProposal` have no callers (`AiReasoningPort.kt:64`, `:73`).
- `ModelDownloader` validates the start URL, but `AiController.openHttps` enables redirects without re-checking the final
  host (`AiController.kt:191`–`:198`). The pinned digest protects content, not the request target.
- `OnDeviceChatModel.release` unbinds the service but does not fail `pending` (`OnDeviceChatModel.kt:109`–`:115`); an
  in-flight line can wait out the 120 s `REPLY_TIMEOUT_MS` (`:83`, `:134`) after the app leaves the screen.
- `android:allowBackup="true"` with no backup rules (`AndroidManifest.xml:6`) covers `filesDir/models`, where the
  344,671,744-byte model is stored (`AiController.kt:47`). Auto Backup's 25 MB quota cannot hold it.

### 3.5 Toolchain and CI

- `compileSdk = 34`, `targetSdk = 34` (`androidApp/build.gradle.kts:10`, `:15`), Compose BOM `2024.09.03` (`:50`), AGP
  8.5.2 and Gradle 8.8. KGP 2.4.20 documents support for Gradle 7.6.3–9.7.0 and AGP 8.5.2–9.3.1, and the build emits
  “Gradle 8.8 is deprecated and will not be supported in future Kotlin Gradle Plugin releases”. AGP 8.5.2 is the
  minimum KGP 2.4.20 supports, and its embedded Kotlin 2.0 reader is the source of the `check` lint noise already
  documented in `CLAUDE.md:26`.
- Google Play requires new apps and updates to target API 36 from 2026-08-31, so the current `targetSdk 34` cannot be
  submitted as-is. The launcher icon is the system placeholder (`AndroidManifest.xml:7`).
- CI runs the invariant check, the Python tests, `./gradlew check` and `assembleDebug`
  (`.github/workflows/ci.yml:24`–`:51`). It never runs `:desktopApp:run --golden=…`; that comparison exists only in the
  local stop gate (`tools/hooks/stop_gate.py:156`–`:158`). The Python mirror is held to the goldens by
  `tools/test_lw_mirror.py:78`–`:81`, so CI would notice a golden edited without a mirror update, but not Kotlin drift.
- `.githooks/pre-commit` must be enabled with `git config core.hooksPath .githooks`; it is not set in this checkout, and
  no README/CLAUDE instruction says to set it. That hook only runs the invariant check. The only Kotlin→golden check is
  the Claude Code Stop hook (`tools/hooks/stop_gate.py`), so it runs in agent sessions but never in git or CI.
- `tools/verify.py` returns BLOCKED when `aws sts get-caller-identity` fails (`tools/verify.py:84`–`:86`). Its
  `--no-remote` mode skips every Gradle task (`:83`), so a contributor with a local JDK cannot use the documented
  one-command gate.

## 4. Suggestions, in priority order

Each item says why it matters (evidence above), the size, whether it changes simulation behaviour (and therefore
`tests/golden/` + `lw_mirror`), and how to prove it. Items marked “backlog” already exist in `docs/backlog.md`; the
suggestion here is a scoped way to do them, not a duplicate.

### P0 — do these before adding features

**P0-1. Make CI enforce the Kotlin goldens (S, no behaviour change).**
CI currently proves only that Kotlin compiles and that the Python mirror matches the goldens. Add one CI step after
`check`:

```sh
set -e
for s in default turmoil feud; do
  extra=$([ "$s" = default ] || echo "--scenario=$s")
  ./gradlew :desktopApp:run --no-daemon --console=plain -q \
    --args="10 0 $extra --golden=tests/golden/$s-10d.txt.gz" | tee /tmp/g-$s.log
  grep -q "Golden *: OK" /tmp/g-$s.log
done
```

This is the same comparison the local stop gate makes (`tools/hooks/stop_gate.py:156`–`:158`) and costs about three
seconds of simulation after the build. It closes the only route by which a kernel change can reach `main` without the
goldens being re-recorded.

**P0-2. Give the app one world, a clock and a save (L, backlog “One shared world”, no golden change).**
Minimum viable shape:

- one `WorldStore` owned by the `Application`/Activity, exposing `StateFlow<WorldState>` and `suspend fun act(event)` /
  `fun tick(duration)`;
- all four view models take the store instead of `world`; delete the four private fields;
- `onStop` writes `SaveManager.serializeEnvelope(store.state)` into `filesDir`, `onCreate` restores with
  `SaveManager.deserializeEnvelope` and falls back to `marketVillage()`;
- a single coroutine ticks `SimulationEngine.advance(…, WorldDuration.hours(1))` while the app is in the foreground.
- Tests: one store instance shared by all VMs; a purchase in inventory is visible in map/dialogue; a death in the duel
  is visible everywhere; save → recreate → load preserves coins, events and relationships.

This also makes the existing `ViewModelTests` meaningful: today they only prove each VM mutates its own copy.

**P0-3. Derive the inventory screen from `world.player.inventory` (S, no golden change).**
`InventoryViewModel` starts with `mapOf("bread" to 3, "herb_bundle" to 1)` (`InventoryViewModel.kt:39`) and keeps its
own counts, while `applyTrade` updates `world.player.inventory`. Replace the hardcoded map with a
`groupingBy { it.value }.eachCount()` of the player's actual inventory, and rebuild `catalog` after each trade (prices
and scarcity change). Extend `ViewModelTests.testInventoryViewModelBuySellEconomy` to assert the count survives a
reload and that selling something never held is impossible.

**P0-4. Repair item conservation and reducer idempotency (M, `golden`).**
Three small kernel changes, one re-record:

1. `applyTheft`: add the item to the thief (`PlayerState.inventory` when the thief is the player, otherwise
   `Npc.resources.items`) and remove it from the player when the player is the owner; update
   `current_behaviour_theft_from_the_player_leaves_the_player_inventory_untouched`.
2. `applyTrade`: refuse the transfer when the seller does not hold the item, and do not trade with a dead NPC.
3. `DefaultWorldReducer.apply`: if `find(event.id) != null`, return `state` before running the branch; update
   `current_behaviour_killing_the_dead_again_repeats_the_cascade` and the ledger-only duplicate test.

Then `python3 tools/regen_golden.py`, update `lw_mirror/reducer.py`, and confirm `python3 tools/mirror_parity.py` and
the three `--golden` runs. These are the clearest “the world does not conserve what it claims to conserve” bugs in the
kernel.

**P0-5. Verify the model on every load, and keep it out of backups (S, no golden change).**
Use the already-written `AndroidModelAssetManager.verifyChecksum` (or hash in `ModelDownloader`) on `attach()` and on
the AI-tab status, not just size; fail `pending` in `OnDeviceChatModel.release`; add
`android:dataExtractionRules`/`fullBackupContent` excluding `models/`. Add a “same size, wrong bytes → not installed”
test at the `ModelDownloader` level (the manager-level test already exists).

**P0-6. Make the app shippable if that is the goal (S/M, no golden change).**
`targetSdk/compileSdk 36` (Play deadline 2026-08-31), a real adaptive icon instead of `@android:drawable/sym_def_app_icon`,
and a Gradle/AGP bump within the KGP 2.4.20 matrix (Gradle 8.8 already warns it is deprecated; AGP 8.5.2 is the minimum
supported, so any upgrade removes the lint noise). Verify with `./gradlew check :androidApp:assembleDebug` plus a
fresh-emulator install. If shipping is not the goal, record that decision in `docs/open-questions.md` so the
placeholder icon and API level are not mistaken for oversights.
