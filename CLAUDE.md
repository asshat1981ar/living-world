# Living-World RPG

Deterministic, event-sourced Kotlin Multiplatform simulation kernel for an Android-first tactical RPG. Read `INSTRUCTIONS.md` for invariants G1–G10 and agent directives; `docs/handoff/last.md` for current state; `docs/backlog.md` for the work queue (worked by the `feature-loop` skill; verify with `python3 -I tools/verify.py`).

# Modules
- `game-core` — kernel: ids, time, events/EventLedger, beliefs, memory, npc, relationships, factions, world (WorldState/WorldReducer), simulation (SimulationEngine, NpcDecisionEngine, ActionValidator), inspector. Must not import `org.livingworld.ai` (G1).
- `game-persistence` — SaveManager, SaveSchemaMigrator, FNV-1a fingerprint.
- `game-ai` — AiReasoningPort, DeterministicAiFallback, AiAdvisedDecisionEngine, `dialogue/` (GroundedDialogueVoice + ChatModel), `ondevice/` (pinned model catalog and integrity checks).
- `game-ui` — sprites, visual adapters, audio, Chimera compose layout engine.
- `androidApp`, `desktopApp` — platform shells.
- Python: `lw_mirror/` (byte-exact kernel port, see below); asset tooling in `scripts/` (`download_model.py` fetches the on-device model into `models/`, gitignored).

# Build & Test Commands
- Run all multiplatform tests: `./gradlew check`
- Run JVM test suite: `./gradlew :game-core:jvmTest`
- Run 30-day simulation runner: `./gradlew :desktopApp:run --args="30 10"`
- Python tests: `python3 -m unittest discover -s tools -p 'test_*.py'`

# Code Style & Guidelines
- Immutability: Use standard Kotlin `copy()` patterns for state transitions.
- Event Sourcing: Every state-altering action must emit a corresponding `GameEvent`.
- Invariants: Strict enforcement of G1–G10 rules at all times.

# Automation hooks (`.claude/settings.json`, scripts in `tools/hooks/`)
- `invariant_guard.py` (before `.kt` edits): blocks newly introduced G1/G8/G9 violations.
- `bash_guard.py` (before Bash): blocks `git add -A|.` / `git commit -a` when an untracked, non-ignored file looks like a secret; runs the stop gate before `git push` or `publish_github.sh` (`LW_SKIP_PREPUSH=1` skips it).
- `session_preflight.py` (SessionStart): reports whether the AWS session is valid and whether the GPU box is running.
- `ci_watch.py` (after a push, then at prompt/session start): polls GitHub Actions in the background and reports pass/fail once, with only the failing step's log tail. Needs `gh` logged in.
- `stop_gate.py` (Stop, tiered): invariants, tool tests, then only the Gradle tasks the changed modules need (game-core -> all four `jvmTest`; one other module -> its `jvmTest`; build files/androidApp/desktopApp -> full `check`), then a G8 determinism tier (`:desktopApp:run` twice per scenario, fingerprints must match; scenarios: the quiet 30-day `default` and a 15-day `turmoil` that starts with a witnessed killing, a killerless death and a theft; `LW_DETERMINISM_RUNS` sets the count) when game-core or desktopApp changed. Per-module digests in `.git/lw-stop-gate/quick.json`. The pre-push gate (`bash_guard`) still runs the full `check`. Measured: unchanged 10 s, one module ~1m50s, first run ~4m50s.
- `telemetry.py`: every guard logs pass/warn/block/skip + seconds to `.git/lw-telemetry/events.jsonl`; `python3 tools/hooks/telemetry.py` prints per-hook counts and flags hooks to demote (never blocked and slow) or tune (bypassed >=25%) once a hook has 20+ runs.
- Conductor mod (outside the repo, `~/.claude/dev-mods/<session>/lw-conductor`): CI status line/toasts from `ci_watch` state, and a login-code `state=` annotation on pasted codes.
- Tests: `python3 -m unittest discover -s tools -p 'test_*.py'`.

# Known issues and decisions (dated per entry)
- Model assets (supply chain; rebuilt 2026-10-21): `ModelAssetCatalog.DEFAULT` is `QWEN3_0_6B_LITERTLM` (litert-community/Qwen3-0.6B int4 `.litertlm`, 344,671,744 bytes); `QWEN3_1_7B_LITERTLM` (977,184,032 bytes) is the optional high-quality model. Both pinned to a commit and sha256, Apache-2.0, ungated, no token. `ModelIntegrity` rejects blank, malformed or "verified" hashes and sizes must match exactly; `AndroidModelAssetManager.getStatus` is only `Ready` for a pinned descriptor with the right size and `verifyChecksum` checks the sha256. `scripts/download_model.py` downloads to `.part`, verifies size and sha256, renames atomically, only fetches https huggingface.co, exits non-zero on failure, and must match the Kotlin catalog (`tools/test_download_model.py`). The GGUF models, stubs, llama.cpp bridge and Hugging Face clients were removed 2026-10-21 (user decision: on-device only, no Hugging Face).
- Dialogue prompt hardening (P3, 2026-10-20): player text is sanitised (`sanitizePlayerText`: one line, no quotes/backticks/brackets/control characters/ChatML tokens, 200 chars); the prompt lists only `speakableFacts` (the confidence floor), the same facts the reply is checked against; the player's words are not on the grounding allow-list; a sentence-initial capitalised word is a claim unless it is in `GroundingCheck.COMMON_OPENERS`. Still open: recording AI choices in the ledger (P9).
- Relationships: `WorldState.relationships` is the single source of truth (the per-NPC `Npc.relationships` graph was removed 2026-10-17; `reputationToward` and `transmitBelief` take the graph as a parameter; old saves still load because `ignoreUnknownKeys = true`).
- Verified 2026-10-17: `BeliefStore` keys no longer embed `Float.toString` (price propositions use `stableFloatText`, same text as JVM for realistic values, so old saves still match). Rest/Work/Flee already emit `NpcRoutineCompleted` (no replay gap). Trade coin creation fixed in `applyTrade` (seller is credited only what the buyer paid). G8 `hashCode()` warnings fixed: `SaveEnvelope.stateHash` now derives from the FNV-1a digest (`SaveManager.stateHashOf`); stance selection uses an explicit string hash.
- G2 in decisions (2026-10-18): `generateCandidates` no longer reads other NPCs' beliefs (it remembers what it already told them via `Memory.Told`), the player's coins, or the world's dead merchants (apprentice inheritance needs an `EntityKilledNpc` or `NpcDied` belief; since 2026-10-19 (P8) it no longer checks the world's `isAlive`, so a false death rumor yields the candidate and `ActionValidator` refuses it; occupation is treated as public). Known gaps: unwitnessed/killerless deaths are never learned (G4 work), (rumor weights were fixed 2026-10-18, see Rumor utility below). The default 30-day run has no deaths or rumors, so its fingerprint does not exercise these paths; `BeliefDrivenDecisionTest` has a scripted killing scenario.
- G4 death cascade (2026-10-18, partial): `applyNpcDeath` now tells absent NPCs who liked the victim (sentiment >0.2) or share an `Npc.factions` entry (hearsay, confidence 0.85), adds `Proposition.NpcDied` for killerless deaths, and fails quests the dead issued. Scarce-trade quest rewards now require the player to be a party to the trade. Not done: starvation deaths (food floors at 0.5, so unreachable), asset redistribution, homicide-problem resolution. `Faction.members` is empty in the TestWorld fixture; `Npc.factions` is what the cascade reads. `DeathCascadeTest` holds the determinism scenario.
- AI behind the validator (2026-10-18): `game-ai` `AiAdvisedDecisionEngine(port)` is an `NpcDecisionEngine`: the port picks among the kernel's own candidates, the pick goes through `ActionValidator`, and an exception, invented action or rejection falls back to `DefaultNpcDecisionEngine`; survival rules (`isSurvivalOverride`) never reach the AI. P9 (2026-10-21): `NpcDecisionEngine.decideWithAdvice` returns an optional `AiAdvice` (source, `AdviceOutcome` FOLLOWED/REJECTED/NOT_A_CANDIDATE/PORT_FAILED, candidate index, explanation); `SimulationEngine.tick` records it as `GameEvent.AiAdviceRecorded` (no state change) just before the action, whose event names it as `causalEventId`. `RecordedAiReasoningPort(records)` plays a run's advice back, so a run steered by a nondeterministic AI repeats event for event (`AiAdvisedDecisionEngineTest`). The default engine never advises, so goldens are unchanged and `lw_mirror` does not port the event (never emitted there). AI dialogue lines change no state and are not recorded. Nothing in the apps uses the advised engine yet (they still build `SimulationEngine()` with the default engine); wiring a real model is a platform decision, and a nondeterministic model is fine for replay because state is rebuilt from events, but it breaks the 30-day fingerprint run, so keep the fallback port for that check.
- Grounded dialogue (2026-10-18, G3): `DialogueGrounding.speakableFacts` (game-core `dialogue/`) is the only source of what an NPC may assert (confidence floor 0.4, source-worded templates); `GroundingCheck.isGrounded` rejects free text that names ids/names/numbers outside those facts (it does NOT catch lower-case invented claims with no names, so prefer kernel-rendered lines). AI-voiced dialogue: `GroundedDialogueVoice(ChatModel)` (game-ai `dialogue/`) applies these rules to any model, keeps a reply's grounded sentences (`GroundingCheck.groundedPart`), strips `<think>` blocks, and counts accepted/salvaged/rejected/failed replies in `stats`. Lines are prepared ahead of time (council decision 2026-10-21): `PregeneratedLines` asks the voice in the background for the next options and the next greeting, keyed by NPC + topic + exact speakable facts (new knowledge makes an old line unreachable), each request reaching the model once; `DialogueViewModel(lines)` shows an AI line only if it is already prepared, otherwise the built-in line, and never swaps text after it is shown. AI lines get a ✨. If rejections are common, add words to `COMMON_OPENERS` rather than loosening the check. AI lines are display only, not ledger events (they change no state; P9 records only AI decisions). On-device AI (2026-10-21, council plan): the AI tab (`AiSettingsScreen`, `AiController`) is opt-in and off by default; `AiEligibility` allows only 64-bit, not-low-RAM phones with >= ~3.4 GiB (the 1.7B model from ~7 GiB); `ModelDownloader` fetches the pinned model into `filesDir/models` (exact size + sha256, atomic); `OnDeviceChatModel` talks to `AiModelService`, which runs LiteRT-LM on CPU with thinking off in the separate `:ai` process, so an OOM or native crash fails one line and `AiSettingsRepository.recordCrash` turns the AI off with a notice. The model is released in `MainActivity.onStop`. The tab shows a speed test (`SpeedVerdict`), model load and reply times, prepared-line stats, and `LineUsage` (share of NPC lines that were the AI's). Not yet run on a real phone: LiteRT calls, the service and the download over the network are untested on a device. Debug APK ~60 MB (LiteRT native libs for arm64 + x86_64).
- Memory in decisions (2026-10-18): `DefaultNpcDecisionEngine.memoryBias` adds up to +-0.6 to a candidate's score from `Memory.Relationship` entries the injected `MemoryRetriever` surfaces for the other party (kindness/cooperation attract; assault/theft/betrayal repel, and make `Attack` more attractive, i.e. a grudge). Only Relationship memories are read; Episodic/Semantic memories are still unused by decisions. The default 30-day run creates no Relationship memories, so its fingerprint does not exercise this; `MemoryDrivenDecisionTest` does.
- Determinism scenarios (2026-10-18): `:desktopApp:run --args='15 0 --scenario=turmoil'` seeds `TurmoilScenario` (2 deaths, 1 theft) so the fingerprint covers the death cascade; fingerprint `9b5f6131bac6a397` at 15 days since the closed economy of 2026-10-19 (changes whenever sim behaviour does, that is expected). The legacy root-level Python simulators (and `test_ui_sprites.py`, which only tested them) were deleted 2026-10-19 (P10); `lw_mirror` replaces them.
- Rumor utility (2026-10-18): `ShareRumor` utility = 0.3 + 0.4 x newsworthiness, where newsworthiness = confidence x reliability / (1 + 0.25 x days old). Fresh certain news (0.7) beats Work (0.5) for about two days, then fades; the NPC picks its most newsworthy untold belief per listener. Turmoil scenario: 77 rumors in 15 days; the quiet default run still has none (nobody holds a shareable belief). Constants are `RUMOR_*` in `NpcDecisionEngine`. Trait boosts (GREEDY merchants always ChangePrice at ~1.0) can still outrank gossip.
- Python kernel mirror (2026-10-18): `lw_mirror/` is a stdlib-only port of the Kotlin kernel (32-bit float emulation in `f32.py`). It is held byte for byte to the Kotlin canonical dumps in `tests/golden/{default,turmoil,feud}-10d.txt.gz` (`:desktopApp:run --args='10 0 [--scenario=turmoil|feud] --dump=<path>'`; `python3 tools/mirror_parity.py` compares; `tools/test_lw_mirror.py` runs it in the tool tests). The stop-gate determinism tier also runs each Kotlin scenario with `--golden=` and blocks if Kotlin no longer matches its golden, so an intended kernel change means: `python3 tools/regen_golden.py`, update `lw_mirror` until `python3 tools/mirror_parity.py` passes, commit both. Verified paths: routine/work/trade/price, rumors and told-memories, death cascade (witness and non-witness), shop inheritance, theft, attack/duel/kill (the feud scenario). Not exercised by any golden (ported from reading, unverified): `ChangeAllegiance`, `Flee`/survival override, faction war problems and quests, NPC-to-NPC trades, `EntitiesMet`, hearsay/FactionReport sources in other witness setups. Inspector, dialogue grounding and `snapshotFor` are not ported. Python `sum()` is compensated on 3.12+, so the reducer's food average is a manual loop; `CanonicalDump.f4` rounds half up while `stableFloatText` rounds half to even (both are ported).
- Performance (2026-10-18, P4): default 90-day run 12.58 s -> 1.80 s (43,200 events), fingerprint `45ca5e3bc580c991` unchanged before and after (since the closed economy: 45,615 events, ~2.0 s, fingerprint `041e2593769b807b`) (commit `0df8053`: `EventLedger` death index and O(1) `find`, `memoryBias` skips the retriever when the NPC has no Relationship memory about the target). `memoryBias` must still rank the NPC's whole memory store: ranking only the target's memories changes which memories make the top `MEMORY_RECALL_LIMIT` and breaks G8/golden parity.

Fixed 2026-10-19: EntitiesMet only initialises a pair whose edge is exactly NEUTRAL (it used to wipe a grudge with no trust/affection); attacks go through `AttackEvents.apply` (game-core `simulation/`), which adds the NpcKilled for a fatal blow exactly once. - Closed economy (2026-10-19): coins are never minted or destroyed; NPC purses + player + `EconomyState.treasury` (starts at 200) stay constant (`SimulationEngineTest.ten_days_of_village_life_neither_mint_nor_destroy_coins`; every golden ends at 1300). `NpcRoutineCompleted.deltaCoins` is a transfer with the treasury, limited by what the paying side has. Non-producers' WORK pays `WORK_WAGE` 0.25 from the treasury; food producers earn only by selling. A worker hungry after a shift (food < 5, coins >= 3) buys 8 food for 3 coins (1 is tax to the treasury) from the producer with the most food that keeps >= 5 (`RationPurchased`; market matching, not NPC knowledge). Every living NPC with coins pays `DAILY_UPKEEP` 3 at the day boundary (`UPKEEP` routine). Quest rewards and the inheritance grant come from the treasury. Constants are in the `SimulationEngine` companion. Chosen by prototype (90 days on lw_mirror): a treasury paying the old 2/h wage empties on day 1; upkeep with wages for producers piles coins on producers and 12 NPCs starve by day 60; this model holds (0 hungry, median ~61 coins at day 90). Known drift: NPCs who never WORK (merchant, elder, herbalist in the default village) go to 0 coins; the best-stocked producers (baker, brewer) reach ~180 by day 90. NPCs still WORK through the night (goal urgency 0.5 keeps all of them active).
- Starvation (2026-10-22, P5, approved): food can reach 0 (the reducer's floor is 0, was 0.5; a ration seller still keeps 0.5). Hunger is the engine's doing, not the reducer's: at each day boundary `StarvationEvents.apply` (game-core `simulation/`, same pattern as `AttackEvents`) gives every living NPC with food <= 0 a recorded `NpcRoutineCompleted` routine `STARVE` (deltaHealth -`STARVATION_DAMAGE` 30) and, if health reaches 0, one `NpcKilled` (no killer, motive "Starvation", cause = the STARVE event); the death cascade then runs as for any killerless death. The dead keep their purses (coins stay conserved). An earlier version (a70304b, reverted in 80b25fd) minted the death inside the reducer and loosened `CharacterizationTest`. The fed default village never starves (nobody gets near 0 food in 90 days), so only the `famine` scenario covers it: `:desktopApp:run --args='10 0 --scenario=famine'` (empty treasury, so no day-0 wages; the blacksmith and the tanner start at 0 food, 0 coins, 20 health; their money goes to the merchant), golden `tests/golden/famine-10d.txt.gz`, mirrored by `lw_mirror.scenarios.famine_seed` and `engine.starve_the_hungry`, held by `mirror_parity.py`, `verify.py`, `stop_gate.py` and CI. `StarvationTest` pins the unit behaviour.

- State digest and save schema (2026-10-22, W2a): the fingerprint is now the **full-state digest** (`StateDigest`), which sees belief content, memories, items, traits, the feelings, the player, the treasury, the quests, the places and the shape of the ledger. The old projection ignored exactly those, so a change there was invisible to every golden (`docs/reports/adversarial-2026-10-22.md` §2.4.1). Relationship edges are keyed by the kind *and* the name of both parties (`npc:merchant->player:player`), so an NPC and a player that share a name are different relationships; the reducers look parties up by kind as well, so a player called "merchant" is not the merchant. The save schema is **v4** and migrates v1/v2/v3 (v3→v4 re-types the edges and recomputes the digest). The canonical dump still prints the historical `a->b` edge form, so the committed goldens stay byte-identical until W2 re-records them.
- Closed economy, for real (2026-10-22, W2b): a trade now needs two parties that exist, a **living** seller that **holds the item** and a buyer that can pay; a theft needs an owner that holds the item and **moves it to the thief**; the shop's stock goes with the shop when it is inherited; a death becomes a public investigation only when a **living NPC that knows about it** asks for it (the guard captain no longer issues a quest for his own murder, and a murder nobody saw produces no quest); a cause can only point backwards (`CausalLinks.originOf` is bounded by the belief's time); and a problem disappears once its investigation is completed or failed. An event that cannot happen is not recorded at all, so the ledger holds no lies. The merchants keep stock (3 bread, 6 goods), the Turmoil scenario gives the blacksmith the stolen blade, and the three goldens were re-recorded once for this wave. The 90-day default run is unchanged (45,615 events, ~1.3 s) and its fingerprint is now **`e6879917a1d38d09`** (`7ae29cd5c158da35` before the review fixes, `e1aea58880101b51` after W2a, `041e2593769b807b` before the full-state digest).

Known gaps, all scheduled in `docs/refactor-plan-2026-10-22.md`: a trade with an unknown seller destroys coins, and a trade can mint stock the seller never held (`applyTrade`); theft moves no item, and theft from the player changes nothing (`applyTheft`); the reducer is not idempotent per event id, so re-applying a recorded event applies it twice; a dead NPC still works, trades and heals; `RelationshipGraph` keys on the identifier only, so `Npc(x)` and `Player(x)` share one edge; the AI snapshot (`snapshotFor`) exposes the last ten global events, so an advisor can see what the NPC could not know (G2); an unwitnessed death still becomes a public murder quest, issued by the guard captain even when the victim is the guard captain; the grounding check only treats capitalised or numeric tokens as claims, so an invented lowercase statement passes (G3); `CausalLinks.originOf` returns the latest matching event, so a cause can point forward (G6); the fingerprint and the canonical dump omit belief content, items, traits, the player, the treasury and quests, so changes there are invisible to every golden; the save gate validates only NPC resources and accepts a blank digest.
