# Living-World RPG

Deterministic, event-sourced Kotlin Multiplatform simulation kernel for an Android-first tactical RPG. Read `INSTRUCTIONS.md` for invariants G1–G10 and agent directives; `docs/handoff/last.md` for current phase.

# Modules
- `game-core` — kernel: ids, time, events/EventLedger, beliefs, memory, npc, relationships, factions, world (WorldState/WorldReducer), simulation (SimulationEngine, NpcDecisionEngine, ActionValidator), inspector. Must not import `org.livingworld.ai` (G1).
- `game-persistence` — SaveManager, SaveSchemaMigrator, FNV-1a fingerprint.
- `game-ai` — AiReasoningPort, DeterministicAiFallback, HuggingFace adapters, on-device GGUF ports.
- `game-ui` — sprites, visual adapters, audio, Chimera compose layout engine.
- `androidApp`, `desktopApp` — platform shells.
- Python: `lw_mirror/` (byte-exact kernel port, see below), `test_huggingface_adapter.py` at root; asset tooling in `scripts/`.

# Build & Test Commands
- Run all multiplatform tests: `./gradlew check`
- Run JVM test suite: `./gradlew :game-core:jvmTest`
- Run 30-day simulation runner: `./gradlew :desktopApp:run --args="30 10"`
- Python tests: `python3 test_huggingface_adapter.py`

# Code Style & Guidelines
- Immutability: Use standard Kotlin `copy()` patterns for state transitions.
- Event Sourcing: Every state-altering action must emit a corresponding `GameEvent`.
- Invariants: Strict enforcement of G1–G10 rules at all times.

# Automation hooks (`.claude/settings.json`, scripts in `tools/hooks/`)
- `invariant_guard.py` (before `.kt` edits): blocks newly introduced G1/G8/G9 violations.
- `bash_guard.py` (before Bash): blocks `git add -A|.` / `git commit -a` when an untracked, non-ignored file looks like a secret; runs the stop gate before `git push` or `publish_github.sh` (`LW_SKIP_PREPUSH=1` skips it).
- `session_preflight.py` (SessionStart): reports whether the AWS session is valid and whether the GPU box is running.
- `ci_watch.py` (after a push, then at prompt/session start): polls GitHub Actions in the background and reports pass/fail once, with only the failing step's log tail. Needs `gh` logged in.
- `stop_gate.py` (Stop, tiered): invariants, tool tests, then only the Gradle tasks the changed modules need (game-core -> all four `jvmTest`; one other module -> its `jvmTest`; build files/androidApp/desktopApp -> full `check`), then a G8 determinism tier (`:desktopApp:run` twice per scenario, fingerprints must match; scenarios: the quiet 30-day `default` and a 15-day `turmoil` that starts with a witnessed killing, a killerless death and a theft; `LW_DETERMINISM_RUNS` sets the count) when game-core or desktopApp changed. Per-module digests in `.git/lw-stop-gate/quick.json`. The pre-push gate (`bash_guard`) still runs the full `check`. Measured: unchanged 10 s, one module ~1m50s, first run ~4m50s.
- `telemetry.py`: every guard logs pass/warn/block/skip + seconds to `.git/lw-telemetry/events.jsonl`; `python3 tools/hooks/telemetry.py` prints per-hook counts and flags hooks to demote (never blocked and slow) or tune (bypassed >=25%) once a hook has 20+ runs.
- Conductor mod (outside the repo, `~/.claude/dev-mods/<session>/lw-conductor`): CI status line/toasts from `ci_watch` state, and a login-code `state=` annotation on pasted codes.
- Tests: `python3 -m unittest discover -s tools -p 'test_*.py'`.

# Known issues (as of 2026-10-17, not yet fixed)
- Model assets (2026-10-18, supply chain): every `ModelAssetCatalog` entry is pinned to a repository commit with Hugging Face's published size and sha256; `ModelIntegrity` rejects blank, malformed or "verified" hashes, sizes must match exactly, and `AndroidModelAssetManager.getStatus` is only `Ready` for a pinned descriptor with the right size (the 303-byte `assets/models/smollm2-*.gguf` stubs are `Error`). `scripts/download_model.py` downloads to `.part`, verifies size and sha256, renames atomically, replaces an invalid existing file, only fetches https huggingface.co, and exits non-zero on failure (`tools/test_download_model.py` also checks its table against the Kotlin catalog). Verified by real download: Qwen 0.5B and SmolLM2-135M; the other two use the published values only. Model filenames are intentional: files are fetched as `qwen2.5-0.5b-instruct-q4_k_m.gguf` and saved on-device as `qwen2.5-0.5b-q4_k_m.gguf` (`targetFileName`). The root-level Qwen GGUF (gitignored) matches. With no native runtime attached, `LocalGgufInferencePort` returns a failure and `AndroidLlamaEngineBridge.generate` throws, so callers fall back deterministically instead of receiving an invented 'action 0'.
- Hugging Face transport (2026-10-18): `HuggingFaceEndpointConfig` rejects any endpoint or Space URL that is not https on huggingface.co, *.huggingface.co or *.hf.space, keeps `apiToken` out of serialization and `toString`, and has a per-request `timeoutMillis` (default 20 s) applied by `HfTransport.postBounded`; caller cancellation is no longer swallowed in the HF, tiered and Qwen paths. Still open from the AI audit: prompt-injection sanitising, GroundingCheck holes, recording AI choices in the ledger, no real HTTP transport yet.
- Relationships: `WorldState.relationships` is the single source of truth (the per-NPC `Npc.relationships` graph was removed 2026-10-17; `reputationToward` and `transmitBelief` take the graph as a parameter; old saves still load because `ignoreUnknownKeys = true`).
- Verified 2026-10-17: `BeliefStore` keys no longer embed `Float.toString` (price propositions use `stableFloatText`, same text as JVM for realistic values, so old saves still match). Rest/Work/Flee already emit `NpcRoutineCompleted` (no replay gap). Trade coin creation fixed in `applyTrade` (seller is credited only what the buyer paid). G8 `hashCode()` warnings fixed: `SaveEnvelope.stateHash` now derives from the FNV-1a digest (`SaveManager.stateHashOf`); stance selection uses an explicit string hash.
- G2 in decisions (2026-10-18): `generateCandidates` no longer reads other NPCs' beliefs (it remembers what it already told them via `Memory.Told`), the player's coins, or the world's dead merchants (apprentice inheritance needs an `EntityKilledNpc` or `NpcDied` belief; since 2026-10-19 (P8) it no longer checks the world's `isAlive`, so a false death rumor yields the candidate and `ActionValidator` refuses it; occupation is treated as public). Known gaps: unwitnessed/killerless deaths are never learned (G4 work), (rumor weights were fixed 2026-10-18, see Rumor utility below). The default 30-day run has no deaths or rumors, so its fingerprint does not exercise these paths; `BeliefDrivenDecisionTest` has a scripted killing scenario.
- G4 death cascade (2026-10-18, partial): `applyNpcDeath` now tells absent NPCs who liked the victim (sentiment >0.2) or share an `Npc.factions` entry (hearsay, confidence 0.85), adds `Proposition.NpcDied` for killerless deaths, and fails quests the dead issued. Scarce-trade quest rewards now require the player to be a party to the trade. Not done: starvation deaths (food floors at 0.5, so unreachable), asset redistribution, homicide-problem resolution. `Faction.members` is empty in the TestWorld fixture; `Npc.factions` is what the cascade reads. `DeathCascadeTest` holds the determinism scenario.
- AI behind the validator (2026-10-18): `game-ai` `AiAdvisedDecisionEngine(port)` is an `NpcDecisionEngine`: the port picks among the kernel's own candidates, the pick goes through `ActionValidator`, and an exception, invented action or rejection falls back to `DefaultNpcDecisionEngine`; survival rules (`isSurvivalOverride`) never reach the AI. Nothing in the apps uses it yet (they still build `SimulationEngine()` with the default engine); wiring a real model is a platform decision, and a nondeterministic model is fine for replay because state is rebuilt from events, but it breaks the 30-day fingerprint run, so keep the fallback port for that check.
- Grounded dialogue (2026-10-18, G3): `DialogueGrounding.speakableFacts` (game-core `dialogue/`) is the only source of what an NPC may assert (confidence floor 0.4, source-worded templates); `GroundingCheck.isGrounded` rejects free text that names ids/names/numbers outside those facts (it does NOT catch lower-case invented claims with no names, so prefer kernel-rendered lines). `HuggingFaceDialogueAdapter` falls back to the kernel line on an ungrounded or failed reply; `DialogueViewModel` no longer has canned facts. The on-device Qwen dialogue path is not wired to the check yet (only the Hugging Face adapter is).
- Memory in decisions (2026-10-18): `DefaultNpcDecisionEngine.memoryBias` adds up to +-0.6 to a candidate's score from `Memory.Relationship` entries the injected `MemoryRetriever` surfaces for the other party (kindness/cooperation attract; assault/theft/betrayal repel, and make `Attack` more attractive, i.e. a grudge). Only Relationship memories are read; Episodic/Semantic memories are still unused by decisions. The default 30-day run creates no Relationship memories, so its fingerprint does not exercise this; `MemoryDrivenDecisionTest` does.
- Determinism scenarios (2026-10-18): `:desktopApp:run --args='15 0 --scenario=turmoil'` seeds `TurmoilScenario` (2 deaths, 1 theft) so the fingerprint covers the death cascade; fingerprint `9b5f6131bac6a397` at 15 days since the closed economy of 2026-10-19 (changes whenever sim behaviour does, that is expected). The legacy root-level Python simulators (and `test_ui_sprites.py`, which only tested them) were deleted 2026-10-19 (P10); `lw_mirror` replaces them.
- Rumor utility (2026-10-18): `ShareRumor` utility = 0.3 + 0.4 x newsworthiness, where newsworthiness = confidence x reliability / (1 + 0.25 x days old). Fresh certain news (0.7) beats Work (0.5) for about two days, then fades; the NPC picks its most newsworthy untold belief per listener. Turmoil scenario: 77 rumors in 15 days; the quiet default run still has none (nobody holds a shareable belief). Constants are `RUMOR_*` in `NpcDecisionEngine`. Trait boosts (GREEDY merchants always ChangePrice at ~1.0) can still outrank gossip.
- Python kernel mirror (2026-10-18): `lw_mirror/` is a stdlib-only port of the Kotlin kernel (32-bit float emulation in `f32.py`). It is held byte for byte to the Kotlin canonical dumps in `tests/golden/{default,turmoil,feud}-10d.txt.gz` (`:desktopApp:run --args='10 0 [--scenario=turmoil|feud] --dump=<path>'`; `python3 tools/mirror_parity.py` compares; `tools/test_lw_mirror.py` runs it in the tool tests). The stop-gate determinism tier also runs each Kotlin scenario with `--golden=` and blocks if Kotlin no longer matches its golden, so an intended kernel change means: `python3 tools/regen_golden.py`, update `lw_mirror` until `python3 tools/mirror_parity.py` passes, commit both. Verified paths: routine/work/trade/price, rumors and told-memories, death cascade (witness and non-witness), shop inheritance, theft, attack/duel/kill (the feud scenario). Not exercised by any golden (ported from reading, unverified): `ChangeAllegiance`, `Flee`/survival override, faction war problems and quests, NPC-to-NPC trades, `EntitiesMet`, hearsay/FactionReport sources in other witness setups. Inspector, dialogue grounding and `snapshotFor` are not ported. Python `sum()` is compensated on 3.12+, so the reducer's food average is a manual loop; `CanonicalDump.f4` rounds half up while `stableFloatText` rounds half to even (both are ported).
- Performance (2026-10-18, P4): default 90-day run 12.58 s -> 1.80 s (43,200 events), fingerprint `45ca5e3bc580c991` unchanged before and after (since the closed economy: 45,615 events, ~2.0 s, fingerprint `041e2593769b807b`) (commit `0df8053`: `EventLedger` death index and O(1) `find`, `memoryBias` skips the retriever when the NPC has no Relationship memory about the target). `memoryBias` must still rank the NPC's whole memory store: ranking only the target's memories changes which memories make the top `MEMORY_RECALL_LIMIT` and breaks G8/golden parity.
- Reducer/engine quirks (2026-10-18, P6): `WorldReducerTest` and `SimulationEngineTest` pin each event branch and each intent. Tests named `current_behaviour_*` (grep for it) pin doubtful behaviour, not a spec: a second NpcKilled repeats the cascade; theft from the player takes nothing; allegiance to an unknown faction dangles and only the first listed faction is left; affection loss alone is remembered as cooperation; actions at the dead leave no event; PriceAdjusted.oldPrice is scarcity-adjusted; Flee does not move; every death (even killerless) becomes a murder quest from the guard captain; opportunities default to issuer elder_rowan. Fixing one is a behaviour change: update the test, goldens and lw_mirror together. Fixed 2026-10-19: EntitiesMet only initialises a pair whose edge is exactly NEUTRAL (it used to wipe a grudge with no trust/affection); attacks go through `AttackEvents.apply` (game-core `simulation/`), which adds the NpcKilled for a fatal blow exactly once. The Android duel never recorded a death before (it checked `Npc.isAlive`, which is already false at 0 health); any new attack producer must use `AttackEvents`. `SimulationKernelTest` was split into `TheftAndRumorKnowledgeTest`, `TacticalCombatTest`, `EconomyAndQuestTest`, `ReplayDeterminismTest`, `NarrativeReconstructionTest`, and two tests moved into `DeathCascadeTest`.
- Closed economy (2026-10-19): coins are never minted or destroyed; NPC purses + player + `EconomyState.treasury` (starts at 200) stay constant (`SimulationEngineTest.ten_days_of_village_life_neither_mint_nor_destroy_coins`; every golden ends at 1300). `NpcRoutineCompleted.deltaCoins` is a transfer with the treasury, limited by what the paying side has. Non-producers' WORK pays `WORK_WAGE` 0.25 from the treasury; food producers earn only by selling. A worker hungry after a shift (food < 5, coins >= 3) buys 8 food for 3 coins (1 is tax to the treasury) from the producer with the most food that keeps >= 5 (`RationPurchased`; market matching, not NPC knowledge). Every living NPC with coins pays `DAILY_UPKEEP` 3 at the day boundary (`UPKEEP` routine). Quest rewards and the inheritance grant come from the treasury. Constants are in the `SimulationEngine` companion. Chosen by prototype (90 days on lw_mirror): a treasury paying the old 2/h wage empties on day 1; upkeep with wages for producers piles coins on producers and 12 NPCs starve by day 60; this model holds (0 hungry, median ~61 coins at day 90). Known drift: NPCs who never WORK (merchant, elder, herbalist in the default village) go to 0 coins; the best-stocked producers (baker, brewer) reach ~180 by day 90. NPCs still WORK through the night (goal urgency 0.5 keeps all of them active).
